## Executive Summary

Whisper.apr 1.0 is a production-grade, WASM-first automatic speech recognition engine implementing OpenAI's Whisper architecture in pure Rust. This specification consolidates the complete feature set for the 1.0 release, spanning Web, CLI, and TUI interfaces.

**Core Capabilities:**
- Real-time streaming transcription via Web Worker architecture
- Zero raw JavaScript policy with DSL-generated code
- Production-grade CLI with real-time TUI (Text User Interface)
- 37MB Pareto-optimal model (whisper-tiny-int8-fb)
- Cross-browser testing via probar 0.5.0
- Observability via Renacer tracing integration

## 1. Architecture

### 1.1 System Overview

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           MAIN THREAD                                    │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐                  │
│  │  Microphone │───>│   Audio     │───>│   Ring      │                  │
│  │  MediaStream│    │   Worklet   │    │   Buffer    │                  │
│  └─────────────┘    └─────────────┘    └──────┬──────┘                  │
│                                               │                          │
│  ┌─────────────┐    ┌─────────────┐          │ postMessage              │
│  │     UI      │<───│   State     │<─────────┤ (Float32Array)           │
│  │   Updates   │    │   Machine   │          │                          │
│  └─────────────┘    └─────────────┘          │                          │
│         ▲                  ▲                  │                          │
│         │                  │                  ▼                          │
│         │           postMessage        ┌─────────────┐                   │
│         │           (result)           │   Worker    │                   │
│         └──────────────────────────────│   Bridge    │                   │
│                                        └─────────────┘                   │
└─────────────────────────────────────────────────────────────────────────┘
                                               │
                          Transferable Object  │ (Float32Array)
                                               ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        TRANSCRIPTION WORKER                              │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐                  │
│  │   Message   │───>│  WhisperApr │───>│   Result    │                  │
│  │   Handler   │    │    Model    │    │   Encoder   │                  │
│  └─────────────┘    └─────────────┘    └─────────────┘                  │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 Data Flow

```
Audio (f32[]) → Resampler (16kHz) → MelFilterbank (80 bins) → Encoder → Decoder → Text
```

### 1.3 Module Structure

```
src/
├── lib.rs          # Public API
├── error.rs        # WhisperError, WhisperResult<T>
├── audio/          # Mel spectrogram, resampling
├── model/          # Transformer encoder/decoder
├── tokenizer/      # BPE tokenization (51,865 tokens)
├── inference/      # Greedy/beam decoding
└── wasm/           # WASM bindings

demos/www-demo/src/
├── lib.rs              # Main entry, state machine
├── worker.rs           # Transcription worker
├── worker_manager.rs   # Worker lifecycle
├── ring_buffer.rs      # SharedArrayBuffer ring buffer
├── audio_worklet.rs    # AudioWorklet processor (DSL)
└── worker_js.rs        # Worker bootstrap (DSL)
```

## 2. Worker-Based Transcription

### 2.1 Implementation Status

| Phase | Status | Components |
|-------|--------|------------|
| Phase 1: Worker Foundation | ✅ COMPLETE | WorkerBridge, message protocol |
| Phase 2: Model Loading | ✅ COMPLETE | Worker fetches/loads model |
| Phase 3: Transcription Pipeline | ✅ COMPLETE | SharedRingBuffer, AudioWorklet |
| Phase 4: Robustness | ✅ COMPLETE | Queue management (max 3), error recovery, memory stability |

### 2.2 Message Protocol

```rust
enum WorkerCommand {
    LoadModel { data: Uint8Array },
    Transcribe { audio: Float32Array, chunk_id: u32 },
    SetOptions { language: Option<String> },
    Shutdown,
}

enum WorkerResult {
    Ready,
    ModelLoaded { size_mb: f64, load_time_ms: f64 },
    Transcription { chunk_id: u32, text: String, rtf: f64 },
    Error { chunk_id: Option<u32>, message: String },
}
```

### 2.3 Threading Model

| Component | Thread | Blocking Allowed |
|-----------|--------|------------------|
| Audio Capture | Main | NO |
| UI Updates | Main | NO |
| Worker Bridge | Main | NO |
| Model Loading | Worker | YES |
| Transcription | Worker | YES |

## 3. CLI and TUI Tools

### 3.1 WAPR-CLI-001: Production & Validation

**Status:** IMPLEMENTED

The `whisper-apr` CLI serves two purposes: a production-grade transcription tool and a rigorous validation harness for the shared Rust core. It uses the exact same `inference` and `audio` crates as the WASM build, ensuring CLI tests validate Web performance.

| Feature | whisper-apr | whisper.cpp | OpenAI Whisper |
|---------|-------------|-------------|----------------|
| **Architecture** | Unified (Native + WASM) | Native C++ | Python/PyTorch |
| **Formats** | .apr (Streaming, LZ4) | GGML | PyTorch `pth` |
| **TUI** | **Ratatui (Real-time)** | Basic Progress | None |
| **VAD** | WebRTC (GMM+RNN) | Silero | Energy-based |
| **Feedback** | Visual (Spectrogram) | Text Log | Text Log |

### 3.2 TUI: The "Genchi Genbutsu" Dashboard

The TUI implements the Toyota principle of *Genchi Genbutsu* ("Go and see") by visualizing the invisible internal state of the engine.

### 3.3 Interaction & Jidoka (Automation with a Human Touch)

The interface follows *Jidoka* by highlighting abnormalities immediately.

**Keybindings:**
*   `q` / `Esc`: Graceful shutdown (flush buffers).
*   `space`: Pause/Resume recording.
*   `t`: Toggle detailed tracing overlay (Renacer spans).
*   `v`: Toggle VAD visualizer (show active speech segments).

**Visual Alerts (Poka-Yoke):**
*   **High Drift:** Time display turns **YELLOW** if processing lag > 500ms.
*   **Low Confidence:** Text segments turn **RED** if log-prob < -1.0.
*   **Audio Clipping:** Spectrogram peaks turn **RED** if input volume > 0dB.

### 3.4 Command Interface

```bash
# Standard Transcription
whisper-apr transcribe test.wav --model tiny --language en

# TUI Mode (Live)
whisper-apr record --live --tui --vad

# Developer Debug Mode (Trace + JSON)
whisper-apr transcribe test.wav --trace performance.json --format json
```

## 4. JavaScript Generation

### 4.1 WAPR-JS-001: Zero Raw JavaScript Policy

**Status:** IMPLEMENTED

All JavaScript is generated from Rust using `probar-js-gen` DSL. Zero raw JavaScript strings permitted.

| Feature | Guarantee |
|---------|-----------|
| Type-safe HIR | Invalid JS unrepresentable |
| Identifier validation | Reserved words rejected |
| Blake3 manifests | Tampering detected |
| Determinism | Same input = same output |
| Forbidden patterns | window, eval blocked |

### 4.2 DSL-Generated Files

| File | Purpose | Tests |
|------|---------|-------|
| `audioworklet_js.rs` | AudioWorklet processor | 20 tests |
| `worker_js.rs` | Transcription worker bootstrap | 11 tests |

### 4.3 Forbidden Patterns

| Pattern | Reason |
|---------|--------|
| `window.` | Workers have no window |
| `document.` | Workers have no document |
| `importScripts` | Use dynamic `import()` |
| `eval(` | Security risk |
| `Function(` | Security risk |

### 4.4 Validation

```rust
let js = generate_worker_js();
let errors = probar_js_gen::validator::validate_worker_js(&js);
assert!(errors.is_empty());
```

## 6. Performance Targets

### 6.1 Latency Budget

| Operation | Target | Max |
|-----------|--------|-----|
| Audio callback | 2ms | 5ms |
| Chunk transfer | 5ms | 20ms |
| UI update | 10ms | 50ms |
| **Total main-thread** | **17ms** | **75ms** |

### 6.2 Transcription Performance

| Model | Chunk Size | Target RTF | Memory |
|-------|------------|------------|--------|
| tiny-int8-fb | 1.5s | 0.5x | 150MB |
| tiny-fp32-fb | 1.5s | 0.8x | 200MB |

### 6.3 Model Selection

**Pareto Optimal:** `whisper-tiny-int8-fb.apr` (37MB)

| Model | Size | Status |
|-------|------|--------|
| tiny-int4-* | 9-24MB | Broken (quantization too aggressive) |
| tiny-int8 (no fb) | 37MB | Broken (missing filterbank) |
| **tiny-int8-fb** | **37MB** | **Working** |
| tiny-fp32-fb | 146MB | Working |
